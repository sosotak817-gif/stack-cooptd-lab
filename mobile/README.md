# 모바일 플레이 도우미 상태

웹 준비 화면: `/mobile-assistant/`. 웹 미리보기는 다른 앱 위의 오버레이가 아닙니다.
현재 구현: 저장 덱 기반 로컬 계산, 제단 전체 on/off 비교, 최신 캡처 1장 메모리 확인, 터치 통과 미리보기.
iPhone: Xcode 시험 앱과 화면 공유 갱신 진단을 준비했습니다. Apple 서명·설치와 실기기 확인이 필요합니다. Android MediaProjection, OCR, 실전 통계 수집과 제단 후보 순위는 후속 단계입니다.

## 기본 계약

- 오버레이에는 버튼·드래그 핸들·터치 리스너를 두지 않습니다. 전 영역 터치·멀티터치·드래그는 게임으로 전달되어야 합니다.
- 제어는 앱 설정과 알림에서 합니다. 게임 입력을 가로채거나 재주입하지 않습니다.
- Android는 NOT_TOUCHABLE + NOT_FOCUSABLE을 사용하며 단일 오버레이의 창 alpha를 OS 최대 obscuring opacity보다 낮게 유지합니다. Canvas 배경 투명도만 낮추는 것은 충분하지 않습니다.
- 실제 게임이 오버레이를 차단하거나 터치를 거부하면 지원 불가로 처리합니다. 우회하지 않습니다.
- iOS는 다이내믹 아일랜드의 Live Activities 요약으로 진행합니다. 아일랜드 영역 터치는 iOS가 처리하며 게임으로 통과하지 않습니다. 상세 설계와 통합 소스는 `ios/README.md`를 확인합니다.
- 캡처는 기기 내에서 처리하고 파일·DB·로그·네트워크에 이미지 데이터를 남기지 않습니다. ImageReader acquireLatestImage + 최대 2버퍼, 분석 중 프레임 폐기, finally에서 Image.close가 필요합니다.
- OCR은 한 작업만 실행합니다. 해상도·주기를 제한하고 캡처 중지·권한 회수 시 모든 프레임을 해제합니다. 숫자 결과도 세션 내 최신 상태만 보관합니다.
- 현재 이미지 확인 UI에는 OCR이 없습니다. 인식 자료와 실제 기기 없이 자동 인식을 완료했다고 주장하지 않습니다.

## 기기 검증 기준

Android 12 이상에서 요약창 바로 아래 버튼, 연속 탭, 길게 누르기, 스와이프, 두 손가락 입력, 화면 회전, 키보드 포커스를 확인합니다. 한 항목이라도 막히면 표시를 중단합니다. 캡처 30분 실행 시 메모리가 계속 증가하지 않고 파일·Cloudflare 업로드가 0인지 확인합니다. 실기기 검증 전 배포 완료로 간주하지 않습니다.
